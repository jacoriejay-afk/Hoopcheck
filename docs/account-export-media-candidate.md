# Original media export candidate

This extends the existing owned-records-v1 durable export; it does not replace or reclassify the 27 record categories. A separate default-off media policy and explicit per-bucket and per-object decisions control disclosure. Source ownership is checked against the reviewed storage catalog. Only a current, non-archived, non-versioned exact object version is eligible. The inventory is immutable per job and remains private; the owner manifest exposes opaque IDs and sizes only. Approved files are delivered through a separately verified server endpoint, not public/signed object URLs. Cancellation, failure or expiry removes the entire inventory. No original filename, path, raw storage metadata, credential, third-party media, or unrelated record is returned. Original bytes may themselves contain third-party information; approval must confirm original disclosure rather than assume redaction. The new 128 MiB technical ceiling is policy-configurable below that bound. Full-file responses are capped at 3 MiB; separately disabled range delivery uses 2 MiB chunks, a fixed trusted Storage origin, exact Content-Range/size and a strong ETag across chunks, and repeated caller/locator proofs. Native writes directly to a temporary cache file; web assembles bounded Blob parts and both offer cancellation. Larger-than-bound and external provider files, ownerless legacy objects, versioned storage, redaction tools and durable staging remain unresolved. Range behavior requires real isolated Storage and signed-device acceptance. A changing object becomes unavailable rather than substituting another file. Full legal fulfillment stays incomplete. No hosted registration or execution.
