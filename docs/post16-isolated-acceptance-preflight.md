# Isolated local acceptance preflight (POST16)
Owner tracker #1075. Do not change the frozen Build 16 branch or production.
The existing signed HTTP harness pins the PR17 project; this companion script checks the local web process environment before any acceptance run. It makes no network calls, starts no server and changes no infrastructure.
## Offline check
- Run `node scripts/check-isolated-acceptance-env.mjs --self-test` (synthetic fixtures, no secrets).
- In a clean isolated checkout with no .env or .env.local or .env.development files, use an operator-controlled fresh shell. Set HOOPCHECK_ACCEPTANCE_MODE=isolated-local, NEXT_PUBLIC_SUPABASE_URL to the exact PR17 test origin, NEXT_PUBLIC_SITE_URL to a loopback origin with a port, STRIPE_CHECKOUT_ENABLED=false and STRIPE_CHECKOUT_MODE=test. Obtain the modern publishable key directly from the **test** project's dashboard. Supply it as NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY and HOOPCHECK_ACCEPTANCE_EXPECTED_PUBLISHABLE_KEY independently from that verified source; never commit it or a secret. Do not copy production environment files. Run `node scripts/check-isolated-acceptance-env.mjs` in that same shell.
- The expected-key comparison is not cryptographic project verification. The script checks selected known environment names only; it does not inspect dotenv files, deployed Vercel values, code paths, unknown provider aliases, or runtime traffic. Do not treat PASS as permission to start a server, exercise write paths, or enable providers. Verify loaded configuration and outbound targets independently first. A privileged test server needs a separate reviewed test-only credential and network isolation procedure.
