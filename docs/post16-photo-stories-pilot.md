# Photo Stories pilot — server boundary
Depends on expiring-content safety PR #1131. The server flag HOOPCHECK_PHOTO_STORIES_ENABLED defaults off. No production flag change or migration authorized. Before activation verify full deployed feed_posts schema accepts post_kind=story and community_visible=false, and actual effective SELECT policies enforce membership, both-direction blocks, follower-only audience and expiry (including every share chain). Service role must not be used to read a Story. Photo-only single moderated attachment; server-generated 24-hour expiry; no client expiry, location, tagging, broad audience, or video. Existing permanent posts remain permanent. Expiring content cannot be permanently reshared or sent to persistent inbox; short-lived signed media links are capped by expiration. Existing rows and media are not physically erased merely by expiry; storage lifecycle and retention policy must be rehearsed before public activation. Native Stories composer/viewer, old-client compatibility, video moderation, audience controls, and signed-device testing remain open. No hosted database writes, production changes or new builds.
